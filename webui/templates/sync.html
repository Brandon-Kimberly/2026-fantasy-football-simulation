A sync rewrites data/current/ and adds new transactions to the decision log. It never rewrites a log row, a forecast or a record, and it does three things before writing anything.

1 · preflight
The odds key is tested

Read from {{ key_source }}{% if not key_present %} (none found){% endif %} and tried against the-odds-api. Anything but an accepted key stops the sync here, because a dead key would quietly replace the real lines with the flat 21.5 default (C3).

2 · backup
data/current/ is backed up

Copied to a dated folder under data/local/ (never tracked). The ten newest are kept, and any of them can be restored below.

3 · the run
The usual sync command runs

The tested key goes to that one process and nowhere else: not a job record, a log or this page. The sync checks the key again itself (H5).
