A sync rewrites data/current/ and appends the new transactions to the decision log; it never rewrites a log row, a forecast or a record. Three things happen before anything is written.

1 · preflight
The odds key is proven live first

Read from {{ key_source }}{% if not key_present %} — none found{% endif %}, probed against the-odds-api. Anything but an accepted key stops here: a dead key would silently write the flat 21.5 line over the real ones (C3).

2 · backup
Everything in data/current/ is copied first

To a stamped folder under data/local/ (never tracked), with a restore button below. The ten newest are kept.

3 · the run
The same command you would type

With the verified key injected into that process only — it never enters a job record, a log or this page. The sync checks the key again itself (H5).
